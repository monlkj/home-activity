# 우리집 포인트

각자 개인 회원가입 → 로그인 → 계정 검색으로 가족방 초대 → 초대 수락 순서로 사용하는 한국어 가족 포인트 웹앱입니다. **Vercel 서버 함수와 Neon PostgreSQL**이 인증과 데이터를 관리하며 Supabase는 사용하지 않습니다.

가족방의 승인 담당자는 포인트를 적립하지 않고 활동을 승인·반려합니다. 활동 참여자는 완료 요청을 보내며 승인 후 포인트가 적립됩니다. 로그인 비밀번호와 승인 비밀번호는 별개입니다. 가입 후 승인 비밀번호를 설정할 수 있고, 로그인 비밀번호를 알아도 승인 비밀번호 없이는 승인할 수 없습니다. 각 기기는 서버에서 같은 가족방 데이터를 읽으며 화면이 열려 있을 때 10초마다 최신 내역을 불러옵니다.

## 사용 순서

1. 가족 구성원이 각자 **개인 회원가입**에서 고유 계정 ID(영문·숫자·밑줄 4~30자), 이름, 로그인 비밀번호를 등록합니다.
2. 승인 담당자는 가입 후 **승인 비밀번호 설정**에서 로그인 비밀번호와 다른 비밀번호를 정합니다. 변경하려면 기존 승인 비밀번호가 필요합니다.
3. 한 사람이 **가족방 만들기**로 방을 만듭니다. 만든 사람은 처음에 승인 담당자이며 가족방 관리자입니다.
4. 가족방 관리자는 **계정 검색 · 가족 초대**에서 상대방의 정확한 계정 ID를 검색하고 활동 참여/승인 담당 역할을 선택합니다. 초대와 역할 지정에도 관리자의 승인 비밀번호를 확인합니다.
5. 상대방은 자신의 계정으로 로그인하여 **받은 초대 → 수락**으로 참여합니다. 수락 전에는 가족방에 접근할 수 없습니다.
6. 가족방 관리자는 **승인 담당자 지정**에서 구성원 역할을 바꿀 수 있습니다. 승인 담당자는 최소 한 명 있어야 합니다. 관리자가 다른 승인 담당자를 지정한 뒤 자신을 활동 참여자로 바꿀 수도 있습니다.
7. 활동 참여자가 완료를 요청하면 승인 담당자가 **자신의 승인 비밀번호**를 입력해 승인·반려합니다. 가족방과 승인 권한은 서버에서 검증합니다.

기존 가족 코드 방식으로 사용했다면 먼저 개인 회원가입 후 **이전 가족 코드로 등록한 프로필 연결하기**를 선택하세요. 기존 부모 프로필을 먼저 연결하고, 다른 가족이 각자 가입한 뒤 기존 프로필을 연결합니다. 기존 가족 코드와 프로필 로그인 비밀번호로 확인하며 포인트와 활동 내역을 유지합니다. 기존 프로필 로그인 비밀번호는 개인 계정의 로그인 비밀번호로 자동 이전하지 않습니다.

## Vercel + Neon 배포

1. Vercel에서 GitHub 저장소 `monlkj/home-activity`를 Import합니다. Application Preset은 **Other**, Root Directory는 기본값 `./`입니다. `vercel.json`이 정적 출력 `public`과 서버 함수 `api/family.js`를 설정합니다.
2. Vercel의 **Storage → Create Database** 또는 Marketplace에서 **Neon**을 선택합니다. 무료 요금제와 적절한 지역을 선택하고 `home-activity`에 연결합니다.
3. 프로젝트의 **Settings → Environment Variables**에서 **DATABASE_URL**이 서버 환경 변수로 등록되어 있는지 확인합니다. Production에 반드시 적용해야 하며, Preview·Development에서 쓰려면 해당 환경에도 연결합니다. 다른 이름으로 연결된 경우 서버 변수를 DATABASE_URL로 설정하세요. 값은 데이터베이스 연결 문자열이며 비밀입니다. 채팅이나 GitHub에 올리지 마세요.
4. 환경 변수를 연결한 후 **Deployments → 최신 배포 → Redeploy**합니다. 이미 실행 중인 배포에는 새 환경 변수가 자동 적용되지 않습니다.
5. 앱에서 각자 **개인 회원가입**한 후 위 사용 순서대로 가족방 생성·초대·승인을 확인하세요. 기존 연결 환경 변수는 그대로 사용하며 새 테이블은 자동 생성됩니다.

서버가 처음 데이터베이스에 연결할 때 기존 가족 테이블과 `home_accounts`, `home_account_sessions`, `home_rooms`, `home_invitations` 등의 테이블을 자동 생성합니다. 연결 계정에 테이블 생성 권한이 필요합니다. DATABASE_URL이 없으면 API가 503 오류로 연결 필요 메시지를 표시하며 로컬 저장 방식으로 대체하지 않습니다.

## 로컬 개발과 검증

Node.js 22 이상이 필요합니다.

```sh
npm ci
npm test
npm start
```

실제 앱을 로컬에서 사용하려면 Neon의 개발용 데이터베이스 DATABASE_URL을 안전한 실행 환경 변수로 전달해야 합니다. `.env`를 저장소에 올리지 마세요. 예를 들어 로컬에서만 보관한 `.env`에 값을 넣은 뒤 `node --env-file=.env server.js`로 실행할 수 있습니다. 기본 포트는 3000이고 PORT로 변경 가능합니다. 테스트는 외부 자격 증명 없이 PGlite의 PostgreSQL 엔진을 사용해 실제 SQL과 API를 검증합니다. 운영 Neon 연결은 별도로 확인해야 합니다.

## 인증과 데이터

- 비밀번호는 무작위 salt와 PBKDF2-SHA-256(210,000회) 해시로 서버에만 저장됩니다. API는 비밀번호 해시를 반환하지 않습니다.
- 무작위 세션 토큰을 HttpOnly·SameSite=Strict 쿠키로 전달합니다. Vercel에서는 Secure 속성이 적용됩니다. 데이터베이스에는 토큰의 SHA-256 해시만 저장하며 세션은 7일 후 만료됩니다.
- 요청자의 역할과 소속 가족은 서버 세션으로 확인합니다. 자녀가 요청 본문이나 브라우저 화면을 수정해 부모 ID·역할·포인트를 전달해도 승인 권한이나 적립 금액을 바꿀 수 없습니다.
- 승인과 교환은 데이터베이스 revision 비교를 통해 동시에 발생한 변경을 처리하며, 같은 완료 요청의 중복 승인을 차단합니다.
- 로그인·승인 비밀번호 시도와 요청 수를 서버에서 제한합니다. 승인 비밀번호 설정 여부만 API로 반환하며 로그인 해시나 승인 해시는 반환하지 않습니다.
- 승인 비밀번호 변경은 기존 승인 비밀번호로 확인합니다. 로그인·승인 비밀번호를 잊었을 때 이메일 복구는 아직 없습니다.

이전 localStorage 버전의 기록은 브라우저에 그대로 남겨 두지만 서버로 자동 이전하지 않습니다. 이전 서버 가족은 기존 프로필 연결을 통해 계정 기반 가족방으로 전환할 수 있습니다. 실제 보상 제공은 가족 간에 진행합니다. 개인정보를 다루므로 가족 코드를 외부에 공유하지 말고 추측하기 어려운 비밀번호를 사용하세요.
